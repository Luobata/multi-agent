# Knowledge Wiki 目录导航设计

## 问题与范围

旧版 Wiki 左栏按 Collection 分组，但文档标题和内部 ID 平铺展示。同步来源已经保存的 `metadata.relativePath` 没有进入导航，因此管理员很难一眼区分 Collection、文件夹和文档，也无法判断当前位置。

本次只调整只读浏览体验：不新增 Wiki 实体，不改变 Revision、发布、引用或授权模型，也不把目录浏览与 Knowledge Profile 授权混在一起。

## 产品结果

管理员可以在保留 Published / Latest Revision 切换的前提下，沿下面的目录定位和阅读文档：

```text
KnowledgeBase
└─ Collection
   ├─ metadata.relativePath 派生文件夹
   │  └─ Document
   └─ 未编目条目
      └─ Document / parentId 子文档
```

必须完成：

- Collection、文件夹、未编目条目、文档具有不同字形、字重和行高；
- 每深入一级固定缩进 16px，并显示父子连接线与展开箭头；
- 默认展开 Collection，支持逐级、全部展开和全部折叠；
- 搜索标题、相对路径、Source Ref 和内部 ID，结果保留祖先但不重复展示 ID；
- 选择文档后显示完整面包屑，选中态不只依赖底色；
- 支持 ARIA tree 键盘路径与清晰焦点；
- 区分加载、失败、无 Revision、空 Collection、搜索无结果和未选文档。

本次不做全文检索、跨知识库搜索、目录拖拽、文档编辑、授权编辑、新接口或移动端专用流程。

## 派生规则

1. Collection 顺序沿用 `KnowledgeBase.collections`，空 Collection 也保留。
2. 有效 `parentId` 是人工确认的 Wiki 层级，优先于来源路径。
3. 无有效父文档时，规范化非空 `metadata.relativePath`，最后一段是文档名，之前的段派生为文件夹。
4. 既无有效父文档也无有效路径的文档进入“未编目条目”，不伪造来源目录。
5. 未知 Collection 进入明确的兜底 Collection，不能静默丢失。
6. 文件夹排在未编目条目和文档之前；同类节点采用稳定的中文数字排序。
7. Collection、文件夹和父文档计数包含全部后代文档。
8. 目录树只是浏览器端只读投影，不持久化，也不表达授权。

## 交互规格

- Collection：40px 粘性分区行，显示权威方章和后代文档数。
- 文件夹 / 未编目条目 / 文档：36px 桌面行；触屏环境扩大到 44px。
- 可展开节点：点击或 Enter / Space 切换；右键方向展开或进入首个子项，左键方向收起或回到父项。
- 上下方向键移动到相邻可见节点，Home / End 到首尾。
- 搜索期间祖先临时展开；清空搜索后恢复手动展开状态。
- 文档内部 ID 不再占用目录的第二行，仍可搜索，并保留在右侧元数据证据中。
- 选中文档同时使用边框、4px 左强调条和加粗标题；键盘焦点使用独立 2px 焦点环。

## 状态与恢复

| 状态 | 目录栏 | 阅读栏 / 恢复 |
| --- | --- | --- |
| 加载中 | 明确显示正在读取 Revision | 保持忙碌语义，等待请求 |
| 加载失败 | `role="alert"` 显示错误 | 切换知识库或 Revision 重试 |
| 无 Revision | 说明尚无可浏览版本 | 回目录治理流程生成 Revision |
| 空 Collection | 显示 Collection 与 0 计数 | 补充内容或选择其他 Collection |
| 搜索无结果 | 明确零结果和清空提示 | 修改关键词或按 Escape |
| 已选择 | 目录叶子高亮 | 面包屑、正文、元数据和引用保持联动 |

## 验收

1. `guides/design/colors.md` 显示为 `Collection → guides → design → colors.md`。
2. 有效 `parentId` 的子文档显示在父文档下；未知父文档不会使文档消失。
3. 无路径文档进入“未编目条目”，未知 Collection 有清晰兜底。
4. 搜索路径、Source Ref 或隐藏 ID 都可命中，且只保留命中项及其祖先。
5. 展开、折叠、焦点移动和打开文档可完全使用键盘完成。
6. 文档选择后显示目录面包屑，右侧原有元数据、引用和候选关系不回归。
7. 1440px PC 三栏无页面级横向溢出；窄于既有断点时沿用纵向堆叠。
8. 客户端派生与键盘测试、仓库 `npm run check` 通过。
